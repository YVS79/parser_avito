# 📶 USB 4G модем ZTE MF823D: работа через модем и смена WAN IP

Документ описывает работу AvitoParser через USB-модем **ZTE MF823D** и
безопасную смену WAN IP без перехода на 3G.

## Что делает интеграция

1. Автоматически находит модем и его сетевой адаптер.
2. Направляет трафик парсера через модем, не меняя маршрутизацию Wi-Fi и
   основного Ethernet.
3. При блокировке Avito (HTTP 403/429/439) меняет WAN IP:
   * сначала быстрым переподключением PDN (`DISCONNECT_NETWORK` →
     `CONNECT_NETWORK`);
   * если IP не изменился — перезагрузкой модема (`REBOOT_DEVICE`).
4. Не переключает модем на 3G, не меняет диапазоны и настройки оператора.
5. Остаётся в LTE.

> Модем MF823D работает в режиме сетевой карты (RNDIS/CDC Ethernet):
> компьютер получает адрес `192.168.4.x` (у вас — `192.168.4.202`),
> веб-интерфейс доступен по `http://192.168.4.1`. COM-порт и AT-команды не
> нужны — используется CGI-API модема.

## Результаты проверок на реальном оборудовании

Проверено на ZTE MF823D, оператор МТС:

| Проверка | Результат |
|---|---|
| `DISCONNECT_NETWORK` → пауза 2 с → `CONNECT_NETWORK` | Соединение восстанавливается, WAN IP **остаётся прежним** |
| `Only_WCDMA` (3G) | Модем теряет регистрацию, может показывать красный индикатор. **Не используется** |
| `REBOOT_DEVICE` с `Referer` | Один раз получен новый WAN IP: `100.93.65.240` → `100.120.47.162`, модем снова в LTE |

**Важно:** причинная связь «перезагрузка → новый IP» на одном наблюдении не
доказана. МТС может выдать тот же адрес даже после перезагрузки. Интеграция
не гарантирует смену IP, а проверяет фактический результат и сообщает об
неудаче.

## Как это работает

```
AvitoParser / parser_cls
        │  HTTPS через локальный прокси 127.0.0.1:<port>
        ▼
Локальный egress-прокси (parser/modem/egress.py)
        │  IP_UNICAST_IF = индекс интерфейса модема
        ▼
Сетевой адаптер модема (192.168.4.x)
        │
        ▼
ZTE MF823D ── LTE ── МТС
        ▲
        │  CGI: DISCONNECT_NETWORK / CONNECT_NETWORK / REBOOT_DEVICE
Управление модемом (parser/modem/zte.py)
```

* `IP_UNICAST_IF` принудительно выбирает интерфейс модема для каждого
  исходящего сокета. Wi-Fi/Ethernet не затрагиваются, права администратора не
  нужны.
* CGI-запросы идут напрямую на локальный адрес модема (`192.168.4.1`), а не
  через интернет.
* После перезагрузки модема локальный IP/индекс интерфейса могут измениться —
  привязка обновляется автоматически.
* При старте парсер проверяет выход через модем: пробует несколько способов
  привязки сокета (`IP_UNICAST_IF` + `bind`, `bind` + `IP_UNICAST_IF`,
  только `IP_UNICAST_IF`) и проверяет, что локальный IP соединения совпадает
  с IP модема. Если ни один способ не даёт внешнего соединения, парсинг **не
  запускается**, чтобы не уйти через Ethernet/Wi-Fi.

## Поддерживаемые модемы

| Модем | Режим | Управление |
|---|---|---|
| **ZTE MF823D** | RNDIS/HiLink, `192.168.4.1` (или `192.168.0.1`) | CGI `goform` |
| ZTE MF823, MF79U, MF920 и совместимые | RNDIS/HiLink | CGI `goform` |
| Huawei, Quectel и др. | — | не поддерживаются |

Если веб-интерфейс модема имеет нестандартный адрес, укажите его в
`modem_gateway`. Автоопределение проверяет `192.168.0.1`, `192.168.4.1` и
`192.168.32.1`.

## Быстрая настройка

### 1. Подготовьте модем

1. Вставьте SIM, отключите PIN-код.
2. Подключите модем к USB, дождитесь адаптера `192.168.4.x`.
3. Откройте `http://192.168.4.1` — веб-интерфейс должен работать.
4. Включите автодозвон, чтобы модем сам поднимал интернет:
   `http://192.168.4.1/goform/goform_set_cmd_process?goformId=SET_CONNECTION_MODE&ConnectionMode=auto_dial`

### 2. Включите модем в парсере

В GUI: **«🌐 Прокси и обход блокировок» → «USB 4G модем (ZTE MF823D)»**:

* галочка **«Работать через USB 4G модем»**;
* адрес модема — пусто (автоопределение) или `192.168.4.1`;
* при необходимости пароль веб-интерфейса;
* способ смены IP — **«Быстро, затем перезагрузка модема»**;
* кнопка **«Проверить модем»**.

Или в `config.toml`:

```toml
use_usb_modem = true
modem_gateway = ""                 # пусто = автоопределение
modem_password = ""                # если веб-интерфейс просит пароль
modem_rotation_strategy = "fast_then_reboot"
modem_fast_timeout = 8             # ожидание после быстрого переподключения
modem_fast_attempts = 2            # попыток быстрого переподключения
modem_reboot_on_fail = true        # перезагружать, если IP не изменился
modem_reboot_timeout = 120         # ожидание CGI + LTE + WAN IP после перезагрузки
modem_max_reboots = 1              # максимум перезагрузок за одну смену IP
```

### 3. Для максимальной скорости

```toml
block_threshold = 1       # менять IP после первой блокировки
retry_delay = 1           # пауза перед повтором, сек
modem_fast_attempts = 1   # не тратить время на второй быстрый реконнект
modem_fast_timeout = 6
```

Ориентировочное время:

* успешное быстрое переподключение — **2–5 секунд**;
* неудачное быстрое переподключение + перезагрузка — **40–90 секунд**
  (зависит от прошивки и сети).

## Стратегии смены IP

| `modem_rotation_strategy` | Что делает | Время |
|---|---|---|
| `fast` | Только `DISCONNECT_NETWORK` → `CONNECT_NETWORK` | 2–5 с |
| `reboot` | Сразу `REBOOT_DEVICE` | 40–90 с |
| `fast_then_reboot` (по умолчанию) | Сначала `fast`; если WAN IP тот же — `reboot` | 2–5 с или 40–90 с |

Старые значения `fast_then_mode` и `mode` автоматически заменяются на
`fast_then_reboot` с предупреждением в логе. Переход на 3G не выполняется.

`modem_reboot_on_fail = false` или `modem_max_reboots = 0` отключает
автоматическую перезагрузку: останется только быстрое переподключение.

## Команды CGI

Все команды отправляются с `Referer: http://<gateway>/index.html`.

| Действие | Запрос |
|---|---|
| WAN IP | `goform_get_cmd_process?cmd=wan_ipaddr&multi_data=1` |
| Статус/LTE | `goform_get_cmd_process?cmd=network_provider,network_type,wan_ipaddr,...` |
| Отключить PDN | `goform_set_cmd_process?goformId=DISCONNECT_NETWORK` |
| Подключить PDN | `goform_set_cmd_process?goformId=CONNECT_NETWORK` |
| Перезагрузить | `goform_set_cmd_process?goformId=REBOOT_DEVICE` |

`SET_BEARER_PREFERENCE` в автоматической смене IP **не используется**.
Метод `set_bearer()` остался в клиенте только как низкоуровневый API.

## Проверка без GUI

```bash
python scripts/modem_cli.py --status
python scripts/modem_cli.py --rotate
python scripts/modem_cli.py --rotate --strategy reboot
python scripts/modem_cli.py --rotate --repeat 3 --delay 2
```

Для `--rotate` печатаются исходный IP, новый IP, стратегия и время.

## Диагностика

### Включён Ethernet, и парсер не выходит через модем

Парсер при старте сам проверяет выход через модем и подбирает рабочий режим
привязки. Если в логе появилось сообщение «Не удалось направить трафик через
USB-модем», значит ни один режим не дал внешнего соединения. Проверьте:

1. `route print -4` — есть ли маршрут `0.0.0.0/0` через `192.168.4.1`.
2. `Get-NetIPInterface -AddressFamily IPv4` — метрики `Ethernet 3` и Ethernet.
3. Временно отключите Ethernet: если так работает, проблема в маршруте/привязке.
4. При необходимости добавьте маршрут через модем с высокой метрикой (только
   вручную, осознанно; требует прав администратора).

Парсер не переключается на Ethernet молча: при неудаче он останавливается.

### «USB 4G модем не найден»

1. Проверьте `http://192.168.4.1` в браузере.
2. `ipconfig` — адаптер `Ethernet 3 (Remote NDIS...)`, адрес `192.168.4.x`,
   шлюз `192.168.4.1`.
3. Укажите `modem_gateway = "192.168.4.1"`.
4. Если веб-интерфейс требует пароль — `modem_password`.
5. Отключите VPN/виртуальные адаптеры, перехватывающие `192.168.4.1`.

### WAN IP не меняется

* МТС использует CGNAT (`100.x.x.x`) и может выдавать тот же адрес. Это не
  ошибка парсера: он сообщит «оператор вернул тот же WAN IP».
* Проверьте `modem_reboot_on_fail = true` и `modem_max_reboots = 1`.
* Увеличьте `modem_reboot_timeout` (например, до 180), если модем долго
  загружается.
* Повторите смену позже: IP может смениться на следующем PDN-соединении.
* Убедитесь, что модем не в режиме «только 2G» и не потерял LTE.

### После перезагрузки нет интернета

* Парсер ждёт CGI, регистрацию LTE и WAN IP в пределах
  `modem_reboot_timeout`.
* Если LTE не появился — проверьте покрытие, SIM и баланс.
* Если WAN IP пустой — проверьте настройки APN и автодозвон.

### Включён VPN

VPN может перехватывать трафик раньше, чем сработает привязка к модему.
В этом случае парсер не сможет выйти через модем и (по новой логике) не
запустится, чтобы не работать через VPN/Ethernet.

Что сделать:

* включите split tunneling в VPN и исключите подсеть `192.168.4.0/24`,
  а также `python.exe` / `AvitoParser.exe`;
* либо отключите VPN на время работы парсера;
* либо запускайте парсер на машине/профиле без VPN.

При активном VPN проверка выхода через модем может занимать несколько секунд
из-за таймаутов; парсер сообщит причину в лог и VK.

### Смена IP занимает слишком долго

* `modem_fast_attempts = 1`.
* `modem_fast_timeout = 6`.
* `block_threshold = 1`, `retry_delay = 1`.
* Не используйте `reboot` без необходимости: это самый медленный путь.

## Ограничения

* Поддерживается IPv4.
* Сравнение идёт по WAN-адресу модема (`wan_ipaddr`). При CGNAT внешний
  адрес может отличаться от WAN.
* Прошивки ZTE отличаются набором CGI-полей; при неполном статусе парсер
  продолжает работу с меньшим объёмом данных.
* Смена WAN IP не гарантирована: МТС может повторно выдать тот же адрес.
